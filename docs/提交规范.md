# 提交规范

每次提交说清楚三件事：**改的是哪一块、做了什么、为什么**。

## 格式

```
<类型>(<范围>): <一句话说明，不超过 50 字>

新增：……
修改：……
删除：……
原因：……（可选，改动不明显时写）
```

- 第一行必须有；下面几行按实际情况写，没有的项省略。
- 一次提交只做一件事。两件不相关的改动拆成两次提交。

## 类型

| 类型 | 用在什么时候 |
|---|---|
| feat | 新功能 |
| fix | 修 bug |
| refactor | 重构：行为不变，只改代码结构 |
| perf | 性能优化 |
| art | 接入或调整美术素材、动画、场景 |
| docs | 文档、README |
| chore | 项目配置、插件、构建脚本等杂项 |
| test | 测试 |

## 范围（举例）

`combat` 战斗 · `anim` 动画 · `ui` 界面 · `config` 配置表 · `hotfix` 热更 · `lua` · `hybridclr` · `pool` 对象池 · `event` 事件 · `project` 项目整体

## 例子

```
feat(combat): 普攻第 12 帧通过帧事件开启伤害判定

新增：AttackHitbox.cs，帧事件 OnAttackHit 打开判定框 0.1 秒
修改：Player.controller 攻击状态加动画事件
原因：伤害判定和动画对齐，避免挥刀前就扣血
```

## 阶段 tag

每完成一个阶段打一个 tag，例如 `v0.1-combat-csharp`，方便面试时按阶段回看。
